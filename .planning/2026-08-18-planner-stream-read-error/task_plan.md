# 策划流式读取错误恢复

## Goal

定位策划过程中 `stream read error` 的来源，为可恢复的流式断连增加稳健应对，并通过回归测试和构建验证。

## Phases

- [completed] 审计策划请求、流式解析、代理转发及现有错误处理。
- [completed] 设计并实现安全的恢复、重试或降级机制。
- [completed] 补充回归测试并运行完整验证。
- [completed] 移除断流自动重试，审计现有确认弹窗与策划重入方式。
- [completed] 实现用户确认后才进行非流式重试。
- [completed] 更新回归测试并重新运行完整验证。

## Decisions

- 保留当前工作区中首页拖拽排序修复，不覆盖或回退相关改动。
- ~~仅对明确可重试且尚未产生不可安全合并结果的断流进行自动恢复。~~ 用户明确要求不得自动重试。
- 同时识别浏览器 `reader.read()` 失败和上游 SSE 错误事件中的精确 `stream read error`，但只用于触发用户确认弹窗。
- 用户确认后按当前配置重新发起相同策划；用户取消则不产生第二次 API 请求。是否关闭流式传输仍由 API 配置决定，不在异常处理里擅自修改。

## Errors Encountered

- 首次断流回归测试的模拟 SSE 块只带一个换行，读取器按协议未消费该事件，导致增量断言为空；补足 `\n\n` 事件分隔后重测。
