# 视觉风格图手动填充

## Goal

在视觉风格选择区域的“重新生成风格图”右侧新增“填充当前风格图”按钮，让用户可以明确地用当前风格图替换底部风格图槽位；同时保持现有空槽自动填充、有图不自动覆盖的规则。

## Phases

- [completed] 审计当前风格图生成、选择、自动填充与槽位替换逻辑。
- [completed] 实现按钮、显式替换行为与交互状态。
- [completed] 补充空槽自动填充和有图手动替换回归测试。
- [completed] 运行聚焦测试、全量测试、生产构建，并尝试本地页面验证。

## Decisions

- 新按钮紧邻“重新生成风格图”右侧，标签固定为“填充当前风格图”。
- 自动流程仍只填充空槽，不覆盖已有风格图。
- 用户点击新按钮属于明确授权，可替换已有风格图。
- 保留工作区中批量图片尺寸工具及其他既有未提交改动，不覆盖或重构无关文件。
- 尚未生成当前 AI 风格图时维持原单按钮布局；生成完成后才显示显式填充按钮。

## Errors Encountered

- 首次对整个 `src` 做风格相关关键字搜索输出过大并被截断；已缩小到 `AmazonPlanner.tsx` 的精确字符串与 setter 调用，不依赖截断结果判断实现。
- 更新验证阶段状态时，补丁中的阶段文案写成“全量 Vitest”，与文件内原有“全量测试”不一致而未应用；读取实际内容后按原文重新更新，无源码影响。
- 首次启动开发服务时 npm 参数被解析成 `vite 127.0.0.1`，服务只报告 localhost，浏览器访问 `127.0.0.1` 被拒绝；已停止该会话并直接用 Vite 可执行文件带 `--host 127.0.0.1` 重启，现已明确监听目标地址。
- 浏览器首次失败后停留在内置 `data:` 错误页；即使服务已正确监听，浏览器安全策略仍禁止该错误页重新导航或关闭。按策略没有绕过，临时开发服务已停止；页面层验证以源码复核、完整类型构建和 410 项自动化测试代替。
