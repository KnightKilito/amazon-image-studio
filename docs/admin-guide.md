# 管理员手册

本文是本地管理员文档，也是登录后“使用文档 → 管理员手册”的唯一内容源。站内正文由管理员权限接口提供，不打包进公共前端资源。若源码仓库公开，仓库内本文件本身不保密。示例均为占位值，禁止把实际凭据写进文档。

适用前端工程版本：**v5.0.0**。自己的 New API 是独立服务，仍固定为本文适配的版本；New API 页面没有显示 v5.0.0 是正常的。普通用户教程在工作台“使用文档 → 用户入门”，不用把部署配置、采购 Key 或管理端地址交给普通用户。

### 普通用户开通检查清单

1. 在自己的 New API 创建普通账户，把本站网址、用户名和初始密码私下交给用户。当前不提供本站自助注册和找回密码页面。
2. 若提供直连，在外部中转站准备这个人的有限额度 Key；不要用公共采购 Key 代替。若提供本站代理，先配置好本站采购渠道、价格与用户余额。
3. 登录工作台，打开“设置 → 管理员设置”，在用户分页表格中搜索用户名／昵称／ID，点击对应行的“配置生图”或“配置策划”。
4. 新增生图和策划配置，设置清楚的名称、正确服务商与协议；按需指定初始默认。使用同一个 Key 时也要确认它同时具备文本和图片模型权限。
5. 点击“保存用户配置”。切换用户前先保存；尚未保存的编辑不是已经下发给用户的配置。
6. 用普通账号的独立浏览器窗口验证：配置自动出现，连接字段隐藏，模型和高级选项可调；不会出现管理员设置或管理员手册入口。
7. 告诉用户到“使用文档 → 用户入门”继续学习，不要求其进入 New API 管理端。说明充值应联系谁、充值哪种额度，以及常用配置名称。

### 三个保存动作的区别

| 按钮 | 保存什么 | 不会做什么 |
| --- | --- | --- |
| 保存站点设置 | 全局权限、推荐模型、参考图上限、统一地址默认值及权益阈值 | 不会批量替换旧 Key，不会给钱包加款 |
| 保存用户配置 | 当前选中用户的多份配置及默认配置，包含新增、编辑和撤销 | 不会修改其他用户，也不会覆盖用户自己的模型／高级选项 |
| 预览批量变更／确认批量更换 | 先校验，再一次更新所选管理员配置的 URL 和对应新 Key | 预览本身不写入，不影响用户自定义配置或本站采购渠道 |

看到版本冲突时，重新加载目标用户或批量列表，核对后再编辑；不要直接用旧表单反复提交。保存失败时不要告诉用户配置已经生效。

### 权限设置如何验收

调整权限后点击“保存站点设置”，再用普通用户检查，不能只看管理员自己的界面；管理员具有维护权限，表现可能不同。地址可见、地址可改、创建配置、修改服务商和创建自定义服务商分别控制不同操作，仍要考虑“允许自定义直连”总开关。

管理员配置和本站配置不因这些开关变成可查看连接的配置。模型推荐列表不是代理模型授权清单；仅在列表中添加一个 ID，不会自动开通该模型或设置价格。初次默认配置也不会覆盖用户已经主动保存的选择。

## 01 两个管理端的分工与日常使用

### 统一设置面板（2026-10-28 更新）

右上角只保留原来的“设置”入口，不再另开“账户与服务”弹窗。普通用户可访问“账户与余额”“API 配置”“习惯配置”“数据管理”；管理员额外看到“管理员设置”。管理员专用文档仍在“使用文档”中。

API 配置列表统一容纳三种来源：管理员分配、自定义直连、本站。选择一份配置就确定请求路径，没有第二层路径开关。管理员分配的配置默认名为“管理员配置”，允许重命名及同一用户多份分配，每种用途有一个初始默认。首次默认不覆盖用户已经主动选择的配置。

管理员在“设置 → 管理员设置 → 给用户分配配置”的分页表格中搜索用户，点击该行的“配置生图”或“配置策划”。已有配置直接打开，未分配时创建待填写草稿；仍可新增多份配置。在共用编辑器中填写名称、服务商、URL、个人 Key、模型及高级参数；支持 OpenAI 兼容、fal.ai 和自定义接口映射。最后统一点“保存用户配置”；成功／失败提示紧邻按钮。已有 Key 不回显，留空保留；更换地址或服务商必须填写新 Key。

表格支持 10／20／50 位用户每页及全站搜索，每行显示生图、策划配置数量。“刷新列表与配置”会刷新当前用户列表、数量以及正在编辑的用户配置；有未保存修改时先确认是否放弃。翻页和搜索不会自动提交或删除编辑草稿。

“允许在工作台修改密码（过渡期）”默认开启，点击“保存站点设置”后生效。开启时普通用户和管理员均可在“账户与余额”验证当前密码并修改自己的 New API 密码；关闭时隐藏入口且后端拒绝请求。成功后撤销该用户的工作台会话并要求重新登录，不影响用户配置、钱包和其他用户。每用户 15 分钟最多 5 次提交；密码和安全验证凭证不写入工作台数据库或日志。New API 要求额外验证时必须在其原生页面处理，工作台不会降级绕过。将来提供 New API 用户中心后可关闭此过渡入口；目前未自动开放其公网入口。

普通用户在自己的 API 列表中看到这些配置，但不能改名称或查看、编辑服务商、URL、Key；可以选择／手填模型和调整高级选项。高级选项保存在自己的账号空间，不反向修改管理员模板。管理员更新连接不会清除用户的高级选项。撤销配置会阻止后续调用，不会悄悄换成收费配置。

用户要换自己的服务，在该用途的“管理 → 新建配置”中选择“自定义直连”；要用本站钱包，选择“走本站”。本站配置同样隐藏连接信息，用户可设置名称、模型和高级参数。模型下拉项是推荐，不是唯一可用列表，本站最终以 New API 可用渠道和用户分组权限为准。

### 旧配置项如何保留

原“游客”权限在平台模式中改称“普通用户”：查看地址、修改地址、新建配置、修改服务商、创建自定义服务商五项均独立保留。它们管理用户自己的配置；管理员分配及本站配置始终隐藏连接信息。“允许用户配置自定义直连配置”是普通用户自定义直连的总开关，“允许创建新 API 配置”同时约束自定义和本站配置的创建。管理员可以维护这些权限；直连凭据在浏览器中仍可通过开发者工具提取，界面限制不等于网络级保密。

“图片模型下拉选项”“策划模型下拉选项”继续使用逐项新增／删除的列表；参考图上限也保留。账户退出在“账户与余额”页，不再使用旧的独立管理员登录弹窗。

### 统一地址与批量换站

统一生图／策划 URL 现在**只用于管理员配置**，不修改用户自定义配置或本站代理地址。开启并保存的 URL 会作为新增管理员配置的默认地址。对已有配置，使用“批量更换管理员配置的中转站”：

1. 选择生图或策划用途，点击“加载受影响配置”。
2. 勾选要更新的配置，填写新统一地址，并为每一行填写对应用户的新个人 Key。
3. 点击“预览批量变更”，核对用户 ID、配置名、旧地址和新地址；此时尚未修改数据。
4. 确认后点击“确认批量更换”。缺少任一新 Key、配置被撤销或版本已改变时，整批拒绝，不会只改一半。

仅修改统一地址开关不会把旧 Key 发往新供应商；关闭开关也不自动撤销已提交的批量变更。对于同域名换路径，同样要求重新提供 Key，以确保管理员明确确认目标与凭据。不要使用一个无限额采购 Key 替代各用户的个人 Key。

旧版每用户一份生图／策划分配会兼容读取为命名配置；旧的管理员／自定义／代理选择首次加载时迁移为当前配置选择。不清空账户、钱包、已分配 Key 或浏览器历史。若需回滚，请先按第九节备份数据库及密钥。

**工作台负责“这个用户怎么使用 AI”，自己的 New API 管理端负责“这个用户是谁、本站余额有多少、代理请求怎么计费”。**它们共用同一套用户账户，不需要在两个地方分别注册或手工关联用户。

### 先分清三个入口

| 入口 | 本地地址 | 管什么 |
| --- | --- | --- |
| 我们的工作台 | http://localhost:8091 | 用户使用 AI；管理员分配个人直连配置、设置站点策略 |
| 自己的 New API 管理端 | http://localhost:3003 | 创建用户、账户权限、本站钱包、代理采购渠道与定价 |
| 外部中转站的后台 | 你购买模型服务的网站 | 你的采购余额，以及在那里创建的个人直连 Key 的额度 |

外部中转站即使也采用 New API，仍是另一套独立系统。**你在 localhost:3003 操作的是自己的平台，不是外部中转站。**正式部署后，工作台换成自己的域名；自己的 New API 管理端通过 SSH 隧道访问，不公开给普通用户。

本站管理员使用自己的 New API 管理员账户登录工作台，即可看到管理区域。两个网页的登录会话各自维护，可能需要各登录一次；这不代表存在两套账户。

### 操作速查：应该去哪里

| 我要做什么 | 去哪里操作 | 入口／说明 |
| --- | --- | --- |
| 创建普通用户、设置初始密码 | 自己的 New API | 用户管理／用户列表 → 新增用户 |
| 重置密码、禁用用户、调整账户角色 | 自己的 New API | 用户管理中处理；普通使用者保持普通用户角色 |
| 给某个人分配直连 URL 和 Key | 工作台 | 设置 → 管理员设置 → 用户表格 → 配置生图／配置策划 |
| 分别指定该用户的生图和策划模型／协议 | 工作台 | 编辑该用户的生图配置、策划配置并保存 |
| 默认走直连还是代理 | 工作台 | 管理员区域的“默认走直连配置”；不覆盖用户已明确保存的选择 |
| 是否允许用户填写自己的直连配置 | 工作台 | 管理员区域的“允许用户配置自定义直连配置” |
| 调整界面可选模型列表、参考图数量上限 | 工作台 | 管理员区域 → 统一模型列表和参考图上限 |
| 给用户增加本站钱包余额 | 自己的 New API | 人工核实收款后，在用户管理中调整额度并保留记录 |
| 查看自己的本站余额与近期代理消费 | 工作台 | 设置 → 账户与余额 → 本站钱包 → 刷新余额与账单 |
| 查看平台各用户的代理消费、请求错误 | 自己的 New API | 消费／请求日志等管理页面；不包含浏览器直连的请求 |
| 配置本站代理使用的采购 URL 和 Key | 自己的 New API | 渠道管理；这是平台采购渠道，不是个人直连配置 |
| 配置代理模型映射、售价、分组倍率 | 自己的 New API | 渠道和模型定价／倍率设置 |
| 调整代理生图／策划的默认模型与人民币换算 | 部署配置文件 | 修改 STUDIO_IMAGE_MODEL、STUDIO_PLANNER_MODEL、STUDIO_PLANNER_API_MODE 或 STUDIO_QUOTA_PER_CNY，再重新应用 studio 容器配置 |
| 给某个人的直连 Key 增加额度或撤销 Key | 外部中转站 | 在那个 Key 所属的供应商后台操作，本站不会代为修改 |
| 给你自己的上游采购账户充值 | 外部中转站 | 增加采购余额，不会自动增加任何本站用户的钱包 |
| 阅读管理员操作手册 | 工作台 | 管理员登录 → 使用文档 → 管理员手册 |
| 设置将来免广告的余额门槛 | 工作台 | 管理员区域 → 免广告余额阈值；当前尚未投放广告 |

工作台的“统一模型列表”只是界面可选项，不等于在 New API 或外部中转站开通了模型，也不会修改价格。代理实际允许的模型还受后台配置及 New API 渠道、令牌限制。

### 当前推荐流程：新增一个直连用户

1. **自己的 New API：创建账户。**打开 http://localhost:3003，在用户管理中新建普通用户，例如 demo。此时可以不充值本站钱包。
2. **外部中转站：准备个人 Key。**为这个用户创建独立、有限额度的 Key。已有个人 Key 可以继续使用，无需重新建立上游账户。
3. **工作台：登录管理员。**打开 http://localhost:8091，进入“设置 → 管理员设置”。如果刚刚在另一个网页创建了用户，重新打开此面板以刷新用户列表。
4. **工作台：加载并分配。**搜索目标用户，点击该行“配置生图”，填写中转站 HTTPS URL、个人 Key、模型和协议并保存；再点“配置策划”单独填写，可以共用同一个人的 URL 和 Key。
5. **工作台：保存。**点击“保存用户配置”。编辑旧配置时 Key 留空代表保留原值；改 URL 时必须同时重新填写 Key。点击“撤销这份配置”后保存则撤销该项配置。
6. **普通用户：登录使用。**在无痕窗口用该用户账户登录工作台，确认生图、策划路径为“管理员分配的直连配置”。用户无需再次手工填写 URL 和 Key。

这条流程下，自己的 New API 负责账户登录，但不转发图片、不扣本站钱包。默认直连测试不需要在自己的 New API 中创建采购渠道。

个人 Key 必须在“管理员设置”中选择目标用户后分配。管理员在“API 配置”页新建自定义直连，只会修改管理员自己浏览器里的配置，**不会分配给其他用户**。

### 如果用户要使用本站钱包代理

1. 管理员在自己的 New API 中配置上游采购渠道、模型和价格，并保持上游采购账户有余额。
2. 核对部署中的代理模型与人民币换算，具体步骤见第 02 节“可选：准备代理计费”。
3. 管理员人工收款后，在自己的 New API 中给该用户增加本站额度。
4. 用户在工作台“设置 → API 配置 → 管理 → 新建配置”中选择“走本站”，随后选中这份配置并提交请求；界面会注明扣本站余额。
5. 请求结束后，用户刷新本站钱包；管理员在自己的 New API 中核对消费日志。

用户可以让策划走直连、生图走代理，或反过来，两项选择分别生效。每次看对应功能的模式提示，不要只看钱包余额判断所有请求是否收费。

### 两种余额和三种 Key 不要混用

| 对象 | 保存／管理位置 | 是否给浏览器使用 |
| --- | --- | --- |
| 用户的个人直连 Key | 外部中转站创建，工作台按用户分配 | 是；用户可以提取，所以必须个人独立且有限额 |
| 本站用户内部令牌（之前说的“子 Key”） | 自己的 New API 创建，后台自动管理 | 否；用于代理请求识别该扣谁的本站余额 |
| 平台采购 Key | 外部中转站创建，填在自己的 New API 渠道里 | 否；供本站代理统一采购模型服务 |

**本站钱包余额**只用于代理，由自己的 New API 记账。**个人直连额度**由外部中转站的 Key 限制，本站不查询也不展示；它不一定等于你在上游采购账户中的总余额。

收到用户转账时，先确认购买的是“直连服务额度”还是“本站钱包”，再到对应系统调整。不要把同一笔钱同时发到两边；给本站钱包充值不会让直连 Key 恢复可用，给上游充值也不会自动增加本站钱包。

### 常见疑问与停用流程

- **在 New API 创建了用户，为什么工作台还提示没有配置？**账户已经有了，但个人直连配置尚未分配。回工作台管理员区域选择该用户并配置。
- **本站钱包是 0，能用吗？**直连可以，只要个人 Key 在上游可用；代理不可以。
- **为什么自己的 New API 日志里看不到用户生图？**如果用户选的是直连，请求直接到供应商，不经过自己的 New API。
- **把 URL 填进 New API 的渠道，为什么用户直连没变化？**渠道只影响本站代理。个人直连需要在工作台按用户修改。
- **关闭“允许自定义直连”是否禁用管理员分配的直连？**不会；用户仍可使用管理员分配配置或选择本站代理。此开关也无法阻止用户把已知的 Key 拿到其他客户端使用。
- **切换中转站要改哪里？**直连需要在工作台为相应用户更新 URL 和个人 Key；代理则改自己的 New API 渠道，并核对模型映射和售价。本站钱包不会因此自动迁移、兑换或清零；旧上游的剩余额度需要另行处理。
- **禁用一个用户该怎么做？**先在自己的 New API 禁用账户，再到外部中转站撤销曾分配给他的直连 Key，必要时在工作台撤销分配。仅禁用本站账户，无法让已经被提取的上游 Key 失效。
- **怎么换密码？**过渡期开关开启时，在工作台“账户与余额 → 修改登录密码”处理；关闭或需要额外安全验证时，到自己的 New API 处理。忘记原密码请联系管理员重置。
- **为什么没有在线充值／广告管理？**当前版本保留人工充值，只预留免广告权益规则；没有支付宝、微信自动到账或实际广告投放功能。

### 请求路径说明

默认直连：浏览器登录后领取管理员分配的个人 URL、Key，或者使用用户自己的本地配置，直接请求中转站。参考图与生成结果不经过本站服务器，不扣本站钱包。本站不知道直连 Key 的上游余额，也不能凭浏览器成功提示结算消费。

本站代理：浏览器携带本站会话 → Node 后台 → 自己部署的 New API → 中转站。New API 使用该用户的内部令牌识别消费账户，再使用采购渠道 Key 调用中转站。代理扣本站钱包，也消耗服务器带宽。

Node 只管理会话、配置和权益，SQLite 不保存第二份消费钱包。账户和本站余额以 New API 为准。不要直接改 New API 数据库，不要把直连额度和本站钱包当作同一笔钱。

## 02 本地 Docker 启动：从零到用户能直连生图

本地已有 Docker Desktop 时，优先用本节。**宿主机不必另外安装 Node、MySQL、Redis，也不用开两个终端逐项设置环境变量。**前端在 Docker 构建时自动开启平台模式，Node 和 New API 都在容器中运行。

先跑通“登录 → 创建用户 → 分配个人直连 → 用户使用”。这一步不需要在自己的 New API 中配置上游采购渠道，也不需要给本站钱包充值。

### 第一步：检查 Docker 并进入项目根目录

启动 Docker Desktop，等待引擎就绪，使用 Linux containers 模式。在 PowerShell 执行：

```powershell
Set-Location D:\Program\VueProjects\amazon-image-studio
docker version
docker compose version
```

`docker version` 应同时显示 Client 和 Server；只显示 Client、提示连接不到引擎时，先处理 Docker Desktop 启动问题。后续命令都在项目根目录执行，不是在 deploy/platform 目录。

### 第二步：自动生成一份本地配置

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\platform\init-env.ps1
```

该命令生成 `deploy/platform/.env.local`，不会启动服务，也不会修改已有配置。它自动填好：

| 项目 | 本地默认值或处理方式 |
| --- | --- |
| 工作台访问地址 | http://localhost:8091 |
| 工作台端口 / New API 管理端口 | 8091 / 3003 |
| Node 加密密钥 | 自动生成独立随机值 |
| New API 会话密钥 | 自动生成另一个独立随机值 |
| 代理模型 | 先填默认值，测试直连时不用修改 |
| quota / 元换算 | 先填 500000 作为直连启动阶段占位值，不是正式人民币定价 |

这几个环境变量是容器需要的配置，不等于每次启动都要你手工输入。重复运行脚本会保留现有文件，不重新生成密钥；不能靠删配置文件重置故障，否则原加密数据可能无法读取。

如果以前在 PowerShell 手工设置过同名 `$env:STUDIO_*` 变量，请打开一个新 PowerShell 再继续。终端环境变量的优先级高于 `--env-file`，可能导致你修改文件后看起来“不生效”。

### 第三步：一次启动全部服务

```powershell
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml up -d --build
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml ps
```

首次需要下载镜像、安装前端构建依赖，耗时取决于网络。本地电脑可以构建；不要把这条带 `--build` 的命令搬到原来的 2G 云服务器上。

`ps` 应能看到 web、studio、new-api 三个服务处于运行状态。此时：

| 地址 | 给谁用、做什么 |
| --- | --- |
| http://localhost:8091 | 我们的工作台，管理员和普通用户都从这里登录 |
| http://localhost:3003 | 自己部署的 New API 管理端，仅管理员本地访问 |
| http://new-api:3000 | Docker 内部服务地址，只给 Node 使用，不是浏览器地址 |
| 中转站的 HTTPS URL | 管理员分配给用户的实际模型供应商，不是上述三个地址 |

本地请始终使用 `http://localhost:8091`，不要中途换成 `http://127.0.0.1:8091`，否则与配置的 Origin 不一致，登录或保存可能被拒绝。后端 8787 端口不需要向宿主机公开。

### 第四步：初始化自己的 New API

1. 用浏览器打开 http://localhost:3003。全新数据卷会进入初始化流程；若已经出现登录页，通常代表该数据卷初始化过，不要为了找初始化页删除数据卷。
2. 创建你自己的管理员用户名、密码及确认密码，妥善保存。没有另外一套“工作台管理员密码”；稍后工作台也使用这个账户。
3. 如果初始化流程询问运行模式，选择正常的多用户使用方式，不启用“自用模式”或“演示站点模式”。数据库已由容器使用 SQLite，不需要填写 MySQL 连接地址。
4. 完成后登录 New API 管理端。
5. 在设置页确认：密码登录开启、公开注册关闭；密码传输加密暂关闭；不要为本站账户开启 2FA、Passkey 或登录验证码等当前适配器未接入的验证流程。这不是让你关闭已有正式站点的保护，而是本次新建测试实例的登录兼容条件。
6. 暂时跳过渠道、在线支付和充值配置。默认直连不经过自己的 New API 模型渠道。

本节对应固定版本 `v1.0.0-rc.46`。不要为了寻找某个按钮直接换成 latest；页面名称略有差异时，按上述设置字段的含义查找。若希望启用额外登录验证，应先补齐本站登录适配。

### 第五步：创建一个普通用户

在 New API 管理端打开用户管理／用户列表，新增一个用于测试的用户：

- 填写用户名、初始密码；角色选择普通用户，不要设成管理员。
- 保持账户启用。若有分组选项，先使用 default。
- 先不给该用户充值本站余额，直连测试可以在本站余额为 0 的情况下进行。

用户账户由你自己的 New API 保存，不是在外部中转站注册新账号。外部中转站仍使用你已经为这个人创建好的个人有限额度 Key。

### 第六步：在工作台分配直连配置

1. 打开 http://localhost:8091，使用第四步创建的管理员账户登录。
2. 点击“设置 → 管理员设置”，确认“默认走直连配置”“允许用户配置自定义直连配置”均已开启。
3. 在管理员用户表格点击“刷新列表与配置”，找到刚创建的用户，再点击其“配置生图”或“配置策划”。
4. 点击“新增生图配置”，填写外部中转站 HTTPS URL、该用户的个人有限额度 Key、准确模型名称，按中转站实际支持的协议选择 Images、Responses 或 Chat Completions。大多数普通 Images 生图接口选择 Images，但不要只凭模型名称猜协议。
5. 点击“新增策划配置”，填写对应 URL、Key、策划模型及 Chat Completions／Responses 类型。二者可以使用同一个人的 Key，但模型和协议需要分别填对。
6. 点击“保存用户配置”。

不要填共享无限额采购 Key；直连 Key 会下发到该用户浏览器。也不要把 `http://new-api:3000` 或 `http://localhost:3003` 填成用户直连的中转站 URL。

### 第七步：用普通用户验证

推荐打开浏览器无痕窗口，访问 http://localhost:8091，用第五步创建的普通用户登录，以免和管理员窗口混用 Cookie。

正常结果应为：

- 无需填写设置，就能看到管理员分配的生图、策划模型。
- 当前模式显示管理员直连、不扣本站余额。
- 使用少量参考图试一次策划或生成；成功与否由真实供应商能力及个人 Key 额度决定。
- 浏览器开发者工具 Network 中，AI 请求指向外部中转站域名，不是本站的 /studio-api/ai 路径。
- 本站余额为 0 也不阻止有效的直连请求。
- 普通用户在“使用文档”中没有管理员手册入口；管理员登录时有。

如果直连报跨域错误，需要中转站允许当前网站 Origin。本站不会悄悄改走代理；也不要为解决跨域而把请求绕回小带宽服务器。

### 常用启动、停止与排错命令

这些命令仍在项目根目录执行：

```powershell
# 查看状态和日志
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml ps
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml logs --tail=100 studio new-api

# 暂停；数据和容器都保留
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml stop

# 恢复已创建的容器
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml start

# 修改 .env.local 后应用配置；restart 不会重新读取新的环境变量
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml up -d --force-recreate studio

# 本地源码更新后重新构建
docker compose --env-file deploy/platform/.env.local -f deploy/platform/compose.yml up -d --build
```

不要执行带 `down -v` 的命令：`-v` 会删除数据库数据卷。单纯更新配置或重启不需要重置数据库。

若端口被占用，先确认占用者，不要随意停止其他项目。可在 `.env.local` 中把 `STUDIO_WEB_PORT` 改成 18091、`STUDIO_ORIGIN` 改成 `http://localhost:18091`，把 `NEW_API_ADMIN_PORT` 改成 13000，再执行一次完整 `up -d`。之后浏览器分别访问 18091 和 13000，容器内的 `NEW_API_URL` 不变。

若看不到平台登录页，确认打开的是 8091，而不是先前的 5173 纯前端开发页；本节 Dockerfile 已内置 `VITE_PLATFORM_ENABLED=true`。

### 可选：准备代理计费

你当前主要用直连，可先跳过这一小节。**仅仅启动自己的 New API，并不意味着代理已经能生图。**代理至少还需要：

1. 在自己的 New API 渠道管理中新建与你的中转站协议匹配的渠道，填写采购 URL、采购 Key、允许的模型及分组。不要填写本站用户的内部令牌。
2. 将 .env.local 的 `STUDIO_IMAGE_MODEL`、`STUDIO_PLANNER_MODEL` 和 `STUDIO_PLANNER_API_MODE` 改成这个渠道实际支持的值。模型名称须能通过 New API 的模型映射匹配上。
3. 在 New API 定价／模型倍率设置中核对模型售价；初次验证保持自动重试次数为 0。
4. 核对货币显示。此固定版本默认使用美元展示，内部每美元对应 500000 quota。若改为人民币展示，记下实际的美元兑人民币展示汇率 R，本站配置应为 `STUDIO_QUOTA_PER_CNY=500000/R` 的计算结果，而不是把算式写进文件。例如 R 为 7 时，写 `71428.57142857143`。这是换算示例，不是建议汇率，也不是上游采购价格。
5. 在 New API 用户管理中给测试用户人工增加一笔明确的测试额度；分别查看 New API 与本站钱包，确认同一用户的人民币金额一致。先别给真实用户收费。
6. 修改部署配置后重建 studio 容器，再登录普通用户，在“设置 → API 配置”中新建并选择“本站”配置，用一次小请求核对消费明细和余额变化。

脚本初始写入的 500000 只是让直连环境能够启动的占位值。在完成上述对账前，不要把本站显示的“¥”当作已经校准的人民币余额。若已通过其他方式调整了内部单位，也应按实际单位重新计算。

### 可选：本地改代码时用热更新

只有需要修改前端代码时，才需要宿主机安装 Node 22.13+。可以保留 Docker 中的 New API 和 Node 后台，仅把前端改为 Vite：

1. 把 .env.local 中 `STUDIO_ORIGIN` 改成 `http://localhost:5173`。
2. 在 Compose 的 studio 服务临时添加仅本机使用的端口映射 `127.0.0.1:8787:8787`，重新执行 `up -d`。不要把该映射加入正式公网部署。
3. 在项目根目录执行 `npm ci`，再在同一 PowerShell 中执行：

```powershell
$env:VITE_PLATFORM_ENABLED = 'true'
npm run dev
```

访问 Vite 输出的 5173 地址；账号操作由 Vite 转发到 8787。若 Vite 改用了其他端口，需要同步修改 Origin，或先解决端口占用。恢复 Docker 前端使用时，把 Origin 改回 8091 并重新创建 studio 容器。普通管理员不需要这套开发流程。

## 03 部署到云服务器：本地构建，服务器只运行

本节用于本地流程验证成功之后。对于原来的 2 核 2G、3 Mbps 机器，默认保持直连；代理图片仍会占出口带宽。部署前检查 `free -h` 的 available 和现有服务，不要把“启动成功”当作容量验证通过。

### 第一步：在本地打包镜像

在本地项目根目录运行：

```powershell
docker build -f deploy/platform/Dockerfile.web -t amazon-studio-web:local .
docker build -f deploy/platform/Dockerfile.server -t amazon-studio-server:local .
docker pull calciumion/new-api:v1.0.0-rc.46
docker save -o studio-images.tar amazon-studio-web:local amazon-studio-server:local calciumion/new-api:v1.0.0-rc.46
```

注意：上面 New API 的固定版本应始终为 `v1.0.0-rc.46`。镜像包包含三个服务用到的镜像，服务器不必安装 npm，也不必从源码构建。

### 第二步：生成正式配置

正式环境使用独立配置和密钥，不直接沿用本地测试密钥。在本地 PowerShell 中运行，将示例域名改为你的工作台域名：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\platform\init-env.ps1 -Origin https://studio.example.com -OutputPath .\deploy\platform\.env.production
```

随后编辑 `deploy/platform/.env.production`：

- 确认 `STUDIO_ORIGIN` 等于最终浏览器访问的 HTTPS 域名，不包含路径。
- 默认宿主端口 8091、管理端口 3003 可保留；端口冲突时改成空闲值，后面的反代与 SSH 隧道也要跟着改。
- 按第二节的代理计费步骤校准 quota / 人民币换算和代理模型；如果暂时只用直连，也要记住占位比例不能用于正式钱包收费。
- 两项随机密钥保持不变，不把文件提交到 Git 或发到群里。

若是从本地测试数据迁移到生产，而不是新建正式环境，则必须成套迁移数据库和原加密密钥；不能用新的密钥解密旧数据。本节默认新建正式环境，不自动迁移测试用户。

### 第三步：上传部署文件

以下命令中的 `user@server` 替换成实际 SSH 用户和服务器地址；`~/amazon-studio` 是部署目录示例，不是要求删除或覆盖已有目录：

```powershell
ssh user@server "mkdir -p ~/amazon-studio/deploy/platform"
scp studio-images.tar user@server:~/amazon-studio/
scp deploy/platform/compose.yml user@server:~/amazon-studio/deploy/platform/
scp deploy/platform/.env.production user@server:~/amazon-studio/deploy/platform/.env
```

服务器目录应是：

```text
amazon-studio/
  studio-images.tar
  deploy/platform/
    compose.yml
    .env
```

不需要把 node_modules、完整源码或 dist 单独上传；它们需要的运行内容已经在镜像里。手册也包含在服务端镜像中。

### 第四步：在服务器加载并启动

SSH 登录服务器后运行：

```sh
cd ~/amazon-studio
chmod 600 deploy/platform/.env
docker version
docker compose version
docker load -i studio-images.tar
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml up -d --no-build
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml ps
curl -fsS http://127.0.0.1:8091/studio-api/health
```

健康接口应返回 `{"ok":true}`，它只证明 Node 服务可访问，不代表 New API 已初始化、模型可用或计费正确。正式启动不要漏掉 `--no-build`：服务器这里没有源码，也不应在 2G 机器上构建。

数据保存在 Docker 命名卷中。后续更新保持同一个 Compose 项目名和部署方式；随意改 `-p` 或项目名可能创建另一组空数据卷，让你误以为用户丢失。

### 第五步：接入已有 HTTPS Nginx 站点

原来已经运行着 Nginx 和 Apache，不需要停掉博客或覆盖整份 Nginx 配置。只修改工作台域名对应的 HTTPS server 块，保留已有证书设置；将该站点原来的静态根路由改成以下反代：

```nginx
# 放在工作台域名现有的 HTTPS server { ... } 内，不是另起一个 nginx 进程。
client_max_body_size 24m;

location / {
    proxy_pass http://127.0.0.1:8091;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Origin $http_origin;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_connect_timeout 60s;
    proxy_read_timeout 620s;
    proxy_send_timeout 620s;
}
```

如果改过 STUDIO_WEB_PORT，上面的 8091 也要修改。确保同一个站点旧的 /studio-api、/admin-api、/api-proxy 等 location 没有覆盖这条路由；其他域名的配置保持原样。证书和 80 → HTTPS 跳转沿用当前站点已有设置；尚未配置证书时，先在当前 Nginx／面板完成该域名的 HTTPS。

检查并重载：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

如使用面板管理 Nginx，使用面板对应的配置测试和重载入口。8091、3003 只绑定服务器回环地址，不需要在阿里云安全组开放这两个端口；公网网站只通过原有 80/443 访问。

正式 STUDIO_ORIGIN 使用 HTTPS 时，会话 Cookie 带 Secure。直接用服务器 IP 或 HTTP 地址测试登录可能失败，应使用配置中的 HTTPS 域名。

### 第六步：通过 SSH 隧道初始化正式 New API

在你自己的电脑上打开新终端，运行并保持这个 SSH 连接：

```powershell
ssh -L 13000:127.0.0.1:3003 user@server
```

然后在本机浏览器访问 `http://localhost:13000`。这是服务器上的 New API，不是本地 Docker 的 3003。若服务器管理端口改过，只修改命令右侧的 3003；本地 13000 被占用时可换成其他本地空闲端口。

按第二节第四、第五步初始化管理员、调整登录策略并创建普通用户，再访问正式工作台域名，登录管理员并分配个人直连配置。不要把 New API 管理端另设一个公网入口。

### 第七步：正式验收与更新

上线前至少确认：

- 管理员与普通用户都能在工作台登录，普通用户看不到管理员手册。
- 用户默认直连成功，图片请求没有绕回本站服务器。
- 需要代理时，先完成测试钱包对账、一次小请求及消费日志核对。
- 查看 `docker stats --no-stream` 和宿主 `free -h`，确认现有博客、Apache、Nginx 没有被挤出内存。
- 密钥和数据卷已有可恢复备份。

以后更新：本地重新构建、save 并上传镜像包；服务器执行 docker load，再运行同一条 `up -d --no-build`。只有修改 .env 才需要重新应用对应容器配置，不能靠 restart 读取新的变量。若只改管理员手册，也需重新构建并更新 studio 镜像，因为文档随服务端打包。

排错命令：

```sh
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml logs --tail=100 studio new-api
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml ps
docker stats --no-stream
```

日志每服务最多三份、每份 10 MB。不要在更新时使用 `down -v`，也不要重新生成加密密钥；升级前的备份恢复规则见第九节。

## 04 配置表

| 配置 | 用途 |
| --- | --- |
| VITE_PLATFORM_ENABLED | 构建／开发时启用平台登录，默认关闭 |
| STUDIO_ORIGIN | 唯一允许的本站 Origin；HTTPS 时使用 Secure Cookie |
| STUDIO_WEB_PORT | Docker 映射到宿主机回环地址的工作台端口，默认 8091 |
| NEW_API_ADMIN_PORT | Docker 映射到宿主机回环地址的 New API 管理端口，默认 3003 |
| NEW_API_URL | Node 访问自己 New API 的固定地址，不是外部中转站地址 |
| STUDIO_ENCRYPTION_KEY | 32 字节 Base64 密钥，加密会话、个人配置和内部令牌 |
| STUDIO_DB_PATH | Node 数据库，默认 data/studio.sqlite |
| STUDIO_PORT / STUDIO_HOST | 后端默认 8787 / 127.0.0.1；容器内监听 0.0.0.0 |
| STUDIO_QUOTA_PER_CNY | 1 元本站余额对应的内部 quota，必须与 New API 显示换算一致 |
| STUDIO_IMAGE_MODEL | 新建本站生图配置的初始模型，用户可另选或手填 |
| STUDIO_PLANNER_MODEL | 默认 gpt-6.1-sol；新建本站／管理员策划配置的初始模型，用户可另选或手填；不覆盖已保存的配置 |
| STUDIO_PLANNER_API_MODE | responses（默认）或 chat |
| NEW_API_SESSION_SECRET | New API 会话密钥，与 Node 加密密钥分开保存 |

运行 `npm run admin:server` 现在也是启动新的平台服务；原 MySQL/SHA256 管理服务已移除。旧 config.yaml 不会被删除，其中的数据库配置不再用于平台后端。纯前端开发代理配置仍由原配置读取器处理。

## 05 管理用户与分配个人配置

1. 在受限 New API 管理端创建普通用户，设置初始密码。本站不另建用户账户。
2. 登录本站，进入“设置 → 管理员设置”，管理员区域选择该用户并加载配置。
3. 新增或选择生图配置，填写中转站 HTTPS URL、该用户的有限额度 Key、模型、接口类型。URL 可带 /v1，不能包含查询参数、用户名或密码。
4. 配置策划服务；如果使用同一中转站，可以填写相同 URL、Key，分别指定策划模型和 Chat／Responses 接口。
5. 保存后让用户刷新；配置也会在窗口重新获得焦点及定时刷新时更新。用户不需要填写 URL 和 Key。

编辑已有配置时 Key 输入为空表示保留旧 Key；更换服务地址时请同时换 Key。点击“撤销这份配置”并保存即撤销。服务端仅向对应用户下发完整 Key；管理员编辑接口返回“已保存”标记，不返回旧 Key。

“默认走直连配置”和“允许用户配置自定义直连配置”默认均开启。第一个开关只决定未主动选择用户的默认路径；用户已经保存的选择不会被覆盖。第二个关闭后，自定义配置仍保留在用户本地，但本站不再允许选择使用。

没有直连配置时不会自动调用收费代理。用户需明确选择“本站”配置，界面会提示收费路径。直连跨域失败、上游余额不足、请求超时都不会自动切换代理。

重置密码、禁用账户在 New API 管理端操作。本站会定期重查身份，代理每次校验身份。禁用后务必同时在上游撤销曾下发的直连 Key：用户可能已经提取并在其他客户端使用它。

## 06 钱包、充值和采购渠道

本站钱包只用于代理。人工收款后在 New API 管理端为用户加款并记录收款依据；不要同时给本站钱包和直连 Key 发放同一笔余额。必须向用户说明购买的是哪种额度。

内部 quota 不是人民币。先设置 New API 的人民币显示和销售倍率，再填写对应 `STUDIO_QUOTA_PER_CNY`。若每美元对应 Q 个 quota、人民币展示汇率是每美元 R 元，则每元对应 Q/R 个 quota，此配置允许正小数。用一个测试账户核对“管理员加 10 元 → 本站显示 10 元 → 测试调用消费明细一致”，确认后才能给真实用户充值。Node 仅做显示换算，不参与钱包记账；不要为了改变模型售价而修改历史余额的人民币换算。

代理采购渠道在自己的 New API 内配置外部中转站 URL、采购 Key 和模型映射。采购 Key 可以不设置额外令牌上限，但上游账户仍需有余额；只能留在服务端。不同用户的代理请求用不同的本站内部令牌结算，内部令牌不另设金额上限，仍受本站用户余额及 New API 用户分组的模型权限限制。首次上线将 New API 自动重试次数设为 0，避免上游结果不明时重复发起付费生成；确认供应商行为后再决定是否开启。

换供应商不会迁移或重置本站钱包。检查新供应商模型名称、计价、参数和图片返回形式，先使用测试账户验证。不能假设所有 New API 中转站都完全相同。上游采购余额是你对供应商的预付款，供应商失联后不能自动找回。

免广告权益接口按本站余额严格大于阈值计算，默认阈值 10 元；不是累计充值，也不是直连余额。当前没有实际广告脚本和在线收款接口。

## 07 迁移与将来启用代理

旧用户先创建本站账户，将原先人工发送的个人 URL、Key 分配给对应用户，原上游额度继续有效，不复制为本站钱包。旧浏览器数据保留原空间；平台每个账号使用独立本地历史、个人知识库、笔记和配置。需要迁移自己的历史时，在旧纯前端环境导出，再登录目标账户手动导入。备份可能含用户自己的自定义 Key，分享前需检查。

旧 MySQL 的统一配置可先从旧系统导出 admin_settings 的 admin_access JSON；使用 `npm run platform:import-settings -- path/to/admin-access.json` 在 Node 服务停止时导入。环境变量必须指向实际平台数据库和对应加密密钥。工具不连接、不删除旧 MySQL，遇到已有配置默认拒绝覆盖。

容器部署可先停止 studio 服务，再运行一次性迁移容器（把示例绝对路径换成自己的 JSON 文件）：

```text
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml stop studio
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml run --rm --no-deps -v /absolute/admin-access.json:/import/admin-access.json:ro studio node server/importSettings.mjs /import/admin-access.json
docker compose --env-file deploy/platform/.env -f deploy/platform/compose.yml start studio
```

将来服务器升级后，配置采购渠道、模型价格及测试钱包，再让用户明确选择代理，或关闭默认直连以影响尚未选择的用户。不要静默覆盖已明确选择直连的用户。代理生图／编辑最多一个在途请求，策划最多一个，同一用户最多一个；代理请求体上限 24 MiB。超出时减少／压缩参考图，不能静默降级请求内容。直连保持原处理能力。

## 08 排错

| 情况 | 检查方式 |
| --- | --- |
| 登录失败 | New API 密码登录开启、用户未禁用、版本与登录策略匹配，STUDIO_ORIGIN 正确 |
| 刷新后失去登录 | 加密密钥／New API 会话密钥是否变化；过期需重新登录 |
| 直连跨域失败 | 中转站是否允许本站 Origin；不要启用旧代理当作自动修复 |
| 直连提示余额不足 | 检查上游个人 Key 和采购账户；本站钱包充值对此无效 |
| 代理余额不足 | 查本站 New API 用户余额、内部令牌状态及模型权限 |
| 代理返回 429 | 等待当前请求结束后重试；不要增加自动重试 |
| 返回 413 | 代理请求超 24 MiB；压缩或减少参考图 |
| 图片生成成功但无法下载 | 检查图片 URL 的跨域和有效期；不能认定生成未消费并自动重生成 |
| 代理令牌创建待核实 | 查 New API 中 studio-用户ID-标识的令牌；网络结果不明时后台不会盲目重复创建 |
| 管理员文档加载失败 | 后端部署是否包含 docs/admin-guide.md，当前账户是否为管理员 |
| 图片传输缓慢 | 确认是否选了代理；3 Mbps 出口仍是瓶颈，流式转发不能增加带宽 |

查看后端日志只用于诊断，不应记录请求 Authorization、Cookie、Key、密码或完整请求体。Node 仅返回脱敏错误；New API 管理端可查看消费和失败记录。超时不代表上游未消费，先查账单，不要连续重试生成。

## 09 备份、恢复与更新

最简单一致备份：先停止 Node 与 New API，再备份两份数据卷及两项密钥，随后启动服务。也可使用 SQLite 官方在线备份方式；不能仅在写入过程中复制主 sqlite 文件而忽略 WAL。备份与密钥分开保管，定期恢复演练。

恢复必须同时恢复数据库与匹配的加密密钥。丢失 STUDIO_ENCRYPTION_KEY 后无法解密个人 Key、会话和代理令牌。不要直接更换密钥试图修复故障。

版本更新前备份；在测试环境核对登录／刷新、令牌创建与读取、钱包、直连流量路径、代理和文档 401/403，再替换镜像。新版本可能迁移 New API 数据库，回滚应用时需要对应数据库备份，不要仅换旧镜像。

## 10 文档访问边界

管理员登录本站后，在现有“使用文档”中选择“管理员手册”。普通用户和游客没有入口，即使直接访问 `/studio-api/admin/docs/guide` 也会得到 401／403。文档不写入浏览器离线缓存，退出、角色失效或切换账号后清除正文。

维护时只编辑本文件。不要复制到 src/docs、public 或静态资源目录，否则会进入公开构建。服务端发布必须带上本文件。文档中的示例和链接必须不含真实密钥。

## 11 发布前验证

维护者可运行 `npm test`、`npm run test:platform` 和 `npm run build`。已安装 Docker 时，`npm run test:platform:real` 会创建专用临时 New API 容器，验证登录、令牌、钱包和本地模拟供应商扣费，然后清理该容器；不使用实际中转站或真实资金。

前端依赖的生产审计可用 `npm audit --omit=dev --registry=https://registry.npmjs.org` 检查。此次兼容范围内的更新消除了检查到的生产依赖高危／严重问题，仍有低危及开发工具审计告警；不代表系统已经通过完整安全审计。构建还保留已有的大资源块与 Browserslist 数据过期提示。

本地功能和模拟供应商测试不能代表真实中转站的全部兼容性，也不能代表 2 核 2G、3 Mbps 服务器的承载能力。上线前仍需用少量真实图片验证供应商接口、本站售价与人民币换算，并确认服务器可用内存。
