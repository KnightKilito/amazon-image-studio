# 实施发现

- `标题Prompt.txt` 是当前优先级最高的标题规则：Item Name ≤75，Item Highlight ≤125，二者职责不同。
- 两份历史笔记仍包含旧式“完整标题 ≤200、建议 150–170”规则，与当前 75+125 契约冲突，不能将原文无差别拼接给模型。
- 历史笔记的标题三段式经验仍有价值：第一段适合映射到 Item Name；第二段和第三段的补充属性、替代词、场景适合映射到 Item Highlight。
- 五点有效知识来自两份笔记：设计/穿戴、鞋头、鞋跟/防滑、搭配/场景、注意事项/尺码/材质，且只能使用标题和产品资料中有证据的特征。
- 长描述原文规则较少：有模板、最后放注意事项。需要基于该意图整理为产品身份、结构/体验、场景/搭配、事实注意事项的稳定框架，但不能虚构来源中没有的营销承诺。
- 应排除广告、选品、供应链、退货、物流、定价、图片/视频编排等与 Listing 文案生成无关的段落，避免稀释提示词。
- 最佳部署结构：用 Vite `?raw` 在构建时打包三份 UTF-8 原文，应用运行时无需访问本地绝对路径；请求发送经过冲突消解的精炼知识，查看弹窗同时提供“实际注入内容”和三份原文。
- 用户最终选择更直观的三提示词结构：标题框直接等于 `标题Prompt.txt`；五点框提炼“设计/穿戴、鞋头、鞋跟/防滑、搭配/场景、注意事项”；长描述框提炼“模板结构 + 最后注意事项”。不再把提炼知识与原文节选混成一个超长系统提示词。
