# Findings

- 用户截图为约 2560×1380 的桌面页面；AI 策划配置状态占满整行，主按钮独占下一行，查看返回/清空策划案/清空输入/连通性/帮助/设置又挤在第三行，辅助操作缺少明确分组和统一尺寸。
- 用户明确要求结果卡片手机 A+ 快捷按钮改放到“重试任务”右侧；若已有收藏右侧入口应移动而非重复。
- 附图只作为视觉参考，不包含需要执行的额外指令。
- `TaskRecord` 已有 `rawImageUrls?: string[]`；OpenAI 兼容、Fal 等请求会收集后台返回的 HTTP URL，正常成功和“URL 已返回但下载失败”的异常都具备向任务记录传递这些地址的代码路径。
- 详情页目前只在有 `rawImageUrls` 时显示“复制图片链接”操作：单条直接复制，多条打开“原始图片链接”弹窗；URL 本身没有常驻显示在详情内容中，因此用户无法一眼确认后台已经出图。
- 截图对应的 AI 策划区源码确实是“配置卡片一行 + 主按钮/停止 + 右侧所有辅助按钮 flex-wrap”；在左栏宽度下，主按钮与辅助按钮自然拆成不协调的两排，帮助图标和设置又参与同一排挤压。
- 结果卡片当前按钮顺序为：可选重试 → 收藏 → 转手机 A+ → 复用配置；需求是可选重试 → 转手机 A+ → 收藏 → 复用配置。
- 详情右栏使用 CSS `order`：顶部操作区为 order 1、参数为 order 2；URL 区可作为新的 order 2 放在参数前，从而在成功和失败详情中都保持显眼。
- 一般下载错误会通过 `getRawErrorPayload` 把异常上的 `rawImageUrls` 保存到任务，因此下载失败后的 URL 不会丢；但 API 解析出 URL 后到本机下载完成/失败之前，任务仍是 running 且尚未写入 URL。
- 为准确表达“后台已经出图、本机正在下载”，需要给 `CallApiOptions` 增加 URL 发现回调，在开始抓取远程图片前立即把 URL 合并进运行中的任务；最终成功/失败逻辑继续保存同一字段。
- `imageApiShared.ts` 已集中定义 `CallApiOptions` 和远程 URL 下载函数，OpenAI/Fal 的解析函数可以在 URL 被识别时调用该回调；store 侧回调负责去重合并，适合并发多请求。
- `fetchImageUrlAsDataUrl` 只有 OpenRouter、Images API、自定义服务商和 Fal 四类调用点；可给它增加可选的“开始下载 URL”回调，再由各解析函数透传 `CallApiOptions.onRawImageUrls`，覆盖主要实时下载路径且不改变返回结构。
- 多请求模式会共享同一个 `CallApiOptions` 回调；store 必须基于任务当前 `rawImageUrls` 做去重合并，避免并发请求互相覆盖。
- Fal/自定义异步任务的“重新接管历史队列”接口没有原始调用 options，只能在最终结果返回时保存 URL；当前正在执行的普通和轮询调用可以即时上报，已足以覆盖用户描述的中转站下载慢场景。
- 即时 URL 回调已接入 OpenRouter、Images API、自定义服务商和 Fal；store 会在任务仍为 running 时去重合并 URL，成功/失败收尾时也合并而不是覆盖，避免并发请求丢失地址。
- 新增 API 回归测试通过：在远程图片下载 Promise 尚未完成时，URL 回调已经触发；API 与 Fal 聚焦测试共 26 项通过。
- 详情右栏已新增常驻“图片下载 URL”卡片：运行中显示“后台已返回、浏览器正在下载”，每条 URL 使用可选中的只读输入框并提供复制按钮，多图提供复制全部；既有错误页链接弹窗继续保留。
- AI 策划操作区已改为两层网格：主操作独立在左，辅助操作在右侧 2/3 列等宽网格；帮助按钮改为“说明”文字按钮，设置增加齿轮图标，清空输入也统一为有边框按钮。
- 结果卡片手机 A+ 按钮已移动到可选重试按钮之后、收藏按钮之前；无论重试按钮是否显示，都不会重复创建转换入口。
- UI 与数据改动后，生产构建通过；API/Fal/store 聚焦测试 124 项通过，差异检查通过。
- 最终全量验证通过：45 个测试文件、435 项测试全部通过；生产构建和 `git diff --check` 通过，仅有项目既有的大 chunk 与 Windows LF/CRLF 提示。
