# Listing 三文件知识库实施计划

## 目标
将 Listing 文案右侧改为标题、五点描述、长描述三个独立可编辑提示词框并一起提交；标题默认直接使用 `标题Prompt.txt`，五点和长描述默认根据两份笔记整理；页面底部仅提供查看三份内置知识源的按钮。

## 已锁定决策
- 浏览器运行时不读取本地绝对路径；三份文件在开发/构建阶段整理为随应用部署的 UTF-8 内容。
- 75 字符 Item Name 与 125 字符 Item Highlight 是固定契约，同时在知识库中解释写法与分工。
- 关闭知识库只移除三文件整理出的增强规则，不移除 JSON、字符上限、禁止编造等系统安全契约。
- “查看系统内置知识库”展示来源、适用范围及实际注入内容。
- 用户已否定“精炼知识库整段注入”方案；新方案不再注入整理版知识库，也不提供知识库开关。
- 标题提示词默认值以 `标题Prompt.txt` 最新原文为主体，并追加“无逗号、无独立单词 and”的当前固定规则；五点和长描述是两份笔记与 `SKU标题.docx` 格式要点的清晰、无冲突提炼版，三个框一起随请求发送。
- 查看弹窗只展示三份原文件，不再展示“实际注入内容”。
- Item Name 与 Item Highlight 均不得包含英文逗号、中文逗号或独立单词 `and`；系统固定契约与结果校验同时执行。
- 五点输出格式参考 `SKU标题.docx`：每条包含序号和方括号小标题；长描述包含独立大标题、自然段/列表和最后一句优雅收束语。
- HTML 预览只渲染本地确定性安全转换结果，不直接信任模型 HTML。
- 流式配置开启时提供实时查看；非流式仍可在完成后查看原始返回。
- 标题相关 AI 指令只由 `标题Prompt.txt` 原文（或用户编辑后的标题提示词）和“禁用逗号/独立单词 `and`”组成，不再追加解释标题职责、字符限制或写作方法；字符边界由标题原文、JSON Schema 和本地校验兜底。
- `missingFacts` 是内部资料补全清单，任何“未提供、未说明、资料不足、无法确认”等审计措辞不得进入 Item Name、Item Highlight、五点或长描述。
- 五点和长描述必须是面向消费者的购买文案：优先放大已确认事实的设计价值、穿着体验、搭配和场景，不为了填满结构而公开罗列缺失信息。
- 标题结果新增独立的 `titleAnalysis` 策划说明，由同一次 AI 请求返回；它可以解释图片识别节点、COSMO 商品身份、关键词取舍、字符分配和待确认机会，但不能替代可复制的 Item Name / Item Highlight。
- “不得编造”只限制虚假的客观属性、性能和认证，不应压制合理的审美表达、穿搭联想、场景想象与情绪价值；五点和长描述要允许更有感染力的语言。
- 五点提供整组英文/中文一键复制，仍保留每条独立复制。
- 合规边界不机械禁止“防滑、抓地、舒适、稳定”等通俗营销词；应根据清晰可见结构与行业常识判断，并只禁止虚假量化、认证、保证性或绝对化承诺。
- 继续优化采用当前结果、原始产品资料和参考图进行定向改写；未被用户点名的优质字段应尽量保留，并复用现有流式详情与历史版本机制。

## 错误记录
| 错误 | 处理 |
| --- | --- |
| 仓库没有 `tsconfig.app.json` | 改为检查实际存在的 TypeScript 配置文件，不重复假设该文件名。 |
| 专项测试按 `COSMO 语义图谱` 断言，但源文件原文为 `COSMO语义图谱` | 保持源文件原文，修正测试为空格无关的真实文本断言。 |
| PowerShell 下 `rg` 参数使用 Unix 风格文件通配符时报路径语法错误 | 改用明确文件路径或 `-g` 过滤；同一命令中的生产构建不受影响并已通过。 |
| 生产构建无法写入 `node_modules/.tmp/tsconfig.app.tsbuildinfo`（EPERM） | 当前会话文件权限为只读，需要按权限流程在允许写缓存后重跑构建。 |
| 首轮全量测试有 3 条断言仍匹配旧提示词原文 | 更新为验证原文前缀及新版格式措辞；定向 19 项和全量 373 项测试随后全部通过。 |
| PowerShell 命令中对 `rg` 传入 `src/lib/*.ts` 通配路径时报 Windows 路径错误 | 改用目录参数配合 `-g "*.ts"` 检索。 |
| 新结构上线后的首次定向测试有 8 项失败 | 均为测试夹具和断言仍使用旧五点/长描述格式，导致生成函数进入自动修复并让单响应 mock 被重复消费；更新夹具为新版合法销售文案，并把断言改为验证新契约。 |
| 新增 `titleAnalysis` 后定向测试有 7 项失败 | API 测试夹具尚未返回必填策划说明，导致所有“合法响应”进入第二次修复；同步补充策划说明、更新积极创意提示词断言和标题段落预期。 |
| 更新夹具后仍有 2 项断言匹配旧版缺失信息英文句式 | 改为断言当前固定契约中的公开文案隔离规则与 `missingFacts` 归档规则；26 项定向测试随后全部通过。 |
| 当前 Chrome 浏览器连接不可用 | 不读取浏览器存储，也不要求用户重复输入；改用已连接的本地页面可见文本与代码持久化逻辑核对当前默认提示词。 |
| 上一轮保留的本地页面标签已被清理 | 保留浏览器连接，重新打开 `#listing-copy` 获取当前构建的可见页面状态。 |
| 误用了不存在的 `tabs.open` 方法 | 通过只读接口检查确认当前运行时使用 `tabs.new`，后续不重复调用错误方法。 |
