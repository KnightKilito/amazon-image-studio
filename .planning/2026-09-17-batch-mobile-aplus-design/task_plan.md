# 批量转手机 A+ 功能设计

## Goal

评估现有批量选择、任务队列、多图输出和手机 A+ 转换基建，设计一个兼容不同中转站能力、可控并发、逐项可追踪且失败可重试的“批量将选中图片转为手机 A+”方案。本轮仅计划，不实施。

## Planning Phases

- [completed] 审计批量选择工具栏、选中对象语义和已有批量尺寸/裁剪功能。
- [completed] 审计手机 A+ 单图转换流程、任务模型、输入图与输出图映射。
- [completed] 审计单请求多图 `n`、客户端并发拆单和详情页多输出能力。
- [completed] 比较批量提交策略，确定推荐交互、并发、失败处理和兼容降级。
- [completed] 输出分阶段实施计划、测试矩阵和待用户确认的产品决策。

## Initial Constraints

- 当前轮次只允许读取和规划，不修改业务源码。
- “批量”应以选中的具体输出图片为单位，不能含糊地默认整条任务全部输出。
- 默认方案必须兼容不支持单请求 `n>1` 的中转站。
- 每张源图应产生独立可追踪结果，部分失败不能导致整批结果丢失。
- 复用现有手机 A+ 片数选择、转换提示词、任务分类和历史详情能力，避免另起一套格式。

## Recommended Architecture

### Submission model

- 选中的每一张源图片创建一条独立 AI 任务，固定 `params.n = 1`。
- 不使用“一次请求携带多张不同源图并要求对应返回”，避免模型合图、顺序错位和参考图上限问题。
- 不依赖中转站支持 `n > 1`；`n` 继续只表示同一输入的多个变体。
- 批次只负责组织和限流，真正的输出、URL、错误、重试仍由现有 TaskRecord/详情页负责。

### Selection model

- 批量工具栏继续以任务卡为入口；点击“批量转手机 A+”后，将选中任务展开为具体 `outputImages` 候选。
- 弹窗必须显示“选中 N 条记录，共 M 张图片”，多输出任务逐张列出缩略图，允许取消某一张，杜绝默认首图或静默全部处理的歧义。
- 仅允许状态完成且图片仍存在的输出参与；运行中、失败、无输出任务在弹窗中说明跳过原因。

### Mobile A+ options

- 片数策略默认“自动沿用原任务”：连续母图沿用原 sliceCount，普通图片为 1 张手机 A+。
- 提供“统一指定”1–7 张；统一指定后所有候选使用相同面板数和目标画布。
- 弹窗逐项显示目标尺寸，例如 `1200x900`、`1200x1800`，并提前校验当前 API 的母图支持与最大片数。
- 当前生图 API 配置在批次开始时冻结，整个批次使用同一配置快照。

### Execution and progress

- 推荐并发数固定为 2；不要直接 `Promise.all` 全量提交。后续如有需要再暴露 1/2/3 的本地选项。
- 先创建批次描述，再由 worker pool 启动独立任务；单项结束立即释放一个槽位并启动下一项。
- 批次进度显示：等待、生成中、成功、失败、已停止；关闭进度弹窗不终止批次。
- 某项失败不阻塞其他项；完成后提供“仅重试失败项”。每个失败任务仍能使用现有单任务重试。
- 批次确认后清除历史卡片选择，但保留批次进度入口。

### Reuse and refactoring

- 从现有 `convertOutputToAPlusFormat` 抽出纯函数：根据源任务、源图、目标 mobile 和片数生成 `{ prompt, params, category }`。
- 单图快捷入口继续调用“准备到首页输入区”的适配层；批量入口使用纯规格直接构造 explicitInput。
- 将 `submitTask` 内部的“验证/建任务/执行”拆层，增加可等待单任务完成的内部入口，供有限并发 worker 使用；普通提交 API 行为保持不变。
- 不直接调用 Agent 专用 `callBatchImageSingle`，但复用其“预创建任务、逐项独立状态、allSettled 汇总”的设计思想。

## Deferred Implementation Plan

1. 建立纯逻辑模块：候选图片展开、去重、跳过原因、片数策略、手机 A+ 请求规格。
2. 重构任务提交层：保留现有 `submitTask(): Promise<boolean>`，新增无全局表单副作用、可等待完成的显式任务提交入口。
3. 新增批量转换弹窗：缩略图清单、逐图勾选、片数策略、API 能力提示、预计任务数量。
4. 在 TaskSelectionToolbar 增加手机图标入口，并建立并发数 2 的批次执行器与进度状态。
5. 为批次任务增加通用分组元数据（批次 ID、序号、总数、源任务/源图），支持结果筛选和失败项重试。
6. 可选增强：若要求刷新后继续未启动队列，再增加持久化 queued 状态和启动恢复；首版可先保证已提交任务独立持久化。
7. 补齐单元/集成/UI 测试，再跑全量测试和生产构建。

## Test Matrix

- 选中多个单图任务，候选数与任务数一致。
- 选中包含多输出的任务，展开所有输出且可逐张取消。
- 重复引用同一 imageId 时去重，保留稳定顺序。
- 自动片数与统一片数生成正确的 mobile 尺寸、prompt 和 category。
- 并发峰值不超过 2，单项失败后队列继续。
- 部分成功、全部失败、用户停止、图片丢失均有明确汇总。
- Images、Responses、OpenRouter、Fal、自定义服务商均按 `n=1` 独立请求。
- 更改当前 API 配置不会影响已经开始的批次配置快照。
- 单项详情、原始 URL、重试、切片功能保持可用。

## Product Decisions Awaiting Confirmation

- 多输出任务进入弹窗时，是否默认全选所有输出（推荐），还是默认只选封面首图。
- 首版是否要求刷新页面后恢复尚未启动的队列；若要求，需要引入持久化 queued 状态，实施范围明显扩大。
- 批次完成后是否自动打开“本批次结果”筛选视图，还是只显示 Toast/进度弹窗。
