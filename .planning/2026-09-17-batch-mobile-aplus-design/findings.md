# Findings

- 用户明确要求本轮先计划，收到后续确认再实施。
- 当前工作区包含多项已完成需求和其他用户改动；规划阶段不触碰业务源码。
- 现有批量选择的基本单位是 `TaskRecord`（`selectedTaskIds`），不是单张输出图片；工具栏已支持全选当前页、收藏、下载、删除，但下载会把选中任务的全部 `outputImages` 展开。
- 一个任务允许包含多个 `outputImages`，详情页会在同一任务内切换查看；因此“选中任务”与“选中具体图片”在 `n>1` 任务上并不等价。
- 现有批量调整尺寸不是从历史批量工具栏进入，而是在图片编辑页聚合候选图片后，浏览器本地处理并保存为一条包含多个输出的派生任务。
- 现有裁剪函数以一张母图为输入，生成一条含多个切片输出的派生任务；尚无“多张来源 × 每张若干切片”的批次父子模型。
- 手机 A+ 转换现有入口会先选择面板片数，再调用 `convertOutputToAPlusFormat`，但该函数只把一张输出图写入当前首页输入区和下一次提交分类，本身不提交 AI 任务。
- 当前批量工具栏可以承载新入口，但若直接复用 `selectedTaskIds`，必须明确多输出任务取首图还是全部图；推荐先构建显式源图片列表并让用户确认数量。
- 本地派生任务已有两种可复用模式：单源图切片产生一条多输出任务；同一任务多输出批量放大产生一条多输出任务。它们适合无网络处理，但不适合直接表达“多张独立 AI 请求的部分成功/失败”。
- `convertOutputToAPlusFormat` 的任务分类构造、提示词和目标尺寸计算是可复用资产，但目前函数同时清空全局输入区、设置当前 prompt 和 pending category，属于交互准备函数，不适合作为批量循环体。
- 批量 AI 转换应把“纯构造每张源图的请求规格”和“写入首页当前输入”拆开：单张快捷入口继续写首页；批量入口直接创建多个任务并调用任务执行器。
- 结果卡片只展示任务第一张输出作为封面，多输出在详情页分页；若批量转换结果合并成一条任务，用户无法清晰看到每张源图的独立运行状态和错误，因此 AI 批量更适合一源图一任务。
- 通用 `submitTask` 已支持 `explicitInput`，可为每次提交显式传 prompt、单张输入图、参数和 category，不必反复改写全局首页输入；这是批量转换最关键的现成接口。
- 现有任务执行器会把每个 TaskRecord 的 API 配置快照、输入图、实时 URL、流式预览、成功输出和失败信息独立保存，天然支持“一张源图一个任务”的追踪与重试。
- 当前 `params.n` 的语义是“同一 prompt + 同一组输入生成多张结果”，不是“多张不同输入分别转换”。它不能直接用于选中多张图片的手机 A+ 转换。
- 多图返回基建确实存在，但各 provider 策略不同：普通非流式 Images API 可把 `n` 放进一次请求；Responses/OpenRouter 会在客户端拆成多个并发单图请求再聚合；流式 Images/Codex CLI 也会拆单；Fal 使用单请求 `num_images` 且最多 4。
- 因此用户的判断正确：对于“每张选中图片各自转换”应始终按源图拆成独立 AI 请求；是否由中转站支持单请求多图与本功能无关，也不应成为依赖。
- Agent 的批量图像工具已有“预创建多条任务、每个 item 单独执行、最后汇总”的范例，但代码耦合 Agent round/message；实现时应抽取或仿照其有限并发模式，不直接复用 Agent UI 状态。
- ApiProfile 当前没有通用批量并发数能力字段；新功能需要前端固定保守并发（建议 2）或新增仅本地的批次并发设置，不能无上限 `Promise.all`。
- `submitTask({ explicitInput })` 会独立创建 TaskRecord 并立即 fire-and-forget 执行，但仍会修改部分全局表单/配置状态且无法等待任务结束；批量限流前需要把内部提交过程拆层，不能简单循环调用现有函数。
- Agent 批量实现目前对所有 item 直接 `Promise.allSettled`，适合小规模模型工具调用，但历史页用户可选数量更大；新功能不应照搬无上限并发。
- 单请求多图能力保留价值：同一 prompt/input 的多个变体可以合并在一条详情记录中；它与多源图片批量转换是两类不同需求，不能混用。
- 推荐 V1 不改变中转站协议：每个请求只传一张源图、`n=1`、返回一张普通或连续手机 A+ 母图；这对兼容性最安全。
- 若每个源图产生独立 TaskRecord，现有详情分页仍能兼容服务商意外返回多张图，但正常路径下每条任务只有一个输出，来源和失败边界清晰。
