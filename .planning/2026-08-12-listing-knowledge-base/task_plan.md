# Listing 三文件知识库实施计划

## 目标
将 Listing 文案右侧改为标题、五点描述、长描述三个独立可编辑提示词框并一起提交；标题默认直接使用 `标题Prompt.txt`，五点和长描述默认根据两份笔记整理；页面底部仅提供查看三份内置知识源的按钮。

## 阶段
- [x] 阶段 1：完整读取三份来源，识别有效规则、冲突、过时内容与无关内容。
- [x] 阶段 2：建立可追溯的结构化内置知识库，调整查看界面和请求注入逻辑。
- [x] 阶段 3：补齐知识库开关、来源展示、兼容与请求测试。
- [x] 阶段 4：运行全量测试、类型检查和生产构建。
- [x] 阶段 5：将单提示词与知识库开关迁移为三个独立提示词及旧草稿兼容。
- [x] 阶段 6：简化右侧 UI，底部只保留三份内置知识库原文查看入口。
- [x] 阶段 7：更新请求与持久化测试，完成全量验证。

## 已锁定决策
- 浏览器运行时不读取本地绝对路径；三份文件在开发/构建阶段整理为随应用部署的 UTF-8 内容。
- 75 字符 Item Name 与 125 字符 Item Highlight 是固定契约，同时在知识库中解释写法与分工。
- 关闭知识库只移除三文件整理出的增强规则，不移除 JSON、字符上限、禁止编造等系统安全契约。
- “查看系统内置知识库”展示来源、适用范围及实际注入内容。
- 用户已否定“精炼知识库整段注入”方案；新方案不再注入整理版知识库，也不提供知识库开关。
- 标题提示词默认值必须等于 `标题Prompt.txt` 最新原文；五点和长描述是两份笔记的清晰、无冲突提炼版，三个框一起随请求发送。
- 查看弹窗只展示三份原文件，不再展示“实际注入内容”。

## 错误记录
| 错误 | 处理 |
| --- | --- |
| 仓库没有 `tsconfig.app.json` | 改为检查实际存在的 TypeScript 配置文件，不重复假设该文件名。 |
| 专项测试按 `COSMO 语义图谱` 断言，但源文件原文为 `COSMO语义图谱` | 保持源文件原文，修正测试为空格无关的真实文本断言。 |
| PowerShell 下 `rg` 参数使用 Unix 风格文件通配符时报路径语法错误 | 改用明确文件路径或 `-g` 过滤；同一命令中的生产构建不受影响并已通过。 |
